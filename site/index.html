01 The problem

Building data exists everywhere.
It just doesn’t mean the same thing.

Cities and countries publish rich building information. But every source has its own schema, vocabulary and definitions — so even “height” or “year built” can quietly mean different things.

  • INSPIRE datasets

  • National cadastres

  • Building registers
  • Energy certificates

    02 The idea

    Agree on meaning,
    not on infrastructure.

    Nobody has to change their original data model. Each place maps its data onto a small shared core — and keeps everything else as local detail, clearly labelled.

    Shared

    A common semantic core

    One definition per attribute: same unit, same measurement reference, same code list — in every delivery. This is Tier 1.

    Local

    Your sources, your tools, your extras

    Country- or source-specific attributes travel alongside, with a prefix and a self-description. They never reuse or overwrite a shared name. This is Tier 2.

    Reusable

    A portable data product

    The result is a self-describing package in open formats that any compatible map or tool can read — no country-specific code needed.

    Local ideas can become shared. A Tier 2 attribute can be proposed for the core once the same tested definition exists in at least two independent sources, with a code list, unit, examples and a reviewed version change.

    R Required in every delivery C Core — worldwide meaning X Extended — optional detail E Energy — optional, draft

    Five ground rules that make data comparable

    =

    One meaning

    A matching name and type is not enough. Same unit, same event, same reference, same classification — everywhere.

    null

    Unknown is unknown

    Missing values are null. Never 0, 9999 or a fake class. A zero is a real zero.

    ∅

    No data, no column

    If a delivery has nothing for an attribute, it leaves it out and says so — the map shows that theme as unavailable, with the reason.

    how?

    Say how you know

    Every attribute declares its method: measured, administrative record, inferred, modelled, crowdsourced or derived from geometry. Measured and modelled are never mixed.

    src

    Show where it came from

    Source, source date and coverage travel with each attribute. Coverage is computed from the data, never typed by hand.

    Standing on existing standards

    Primary anchor

    INSPIRE Buildings

    The European data specification for buildings: use values, construction condition, height references, building nature.

    Secondary anchor

    CityGML 3.0

    The OGC model for 3D cities: buildings and building parts, storeys, construction and demolition dates.

    Energy anchor

    CityGML Energy ADE

    An extension for energy modelling; the exact version is pinned in every crosswalk because it is still evolving.

    Guidance for use classes

    Eurostat CC

    The Classification of Types of Constructions helps decide which use class a building belongs to.

    Aligned with, not part of. Contract attribute names are Colouring names, not official INSPIRE or CityGML property names. The contract is a proposed application profile; it is not an official standard and has no endorsement from INSPIRE, OGC, Eurostat or the Colouring Cities Research Programme.

    Where AI helps — and where it doesn’t

    By “AI” we mean an assistant, similar to a chatbot, that can read files and write drafts. It is fast and patient, but it can be confidently wrong. So in this proposal it prepares work and never has the last word. Here is one column going through step 1.

    Example A hypothetical source column

    1. 1 · The assistant suggests

      “The column yr_built looks like construction_year. But the source manual says it records the year a building was registered, which can be years after it was finished. Please check.”

      Good at: reading long manuals, spotting likely matches, raising doubts.

    2. 2 · A person decides

      “Right — here, registration can lag behind completion. We won’t call it the construction year. We keep it as a local column, so nothing is lost.”

      Only people can judge meaning, local context, and whether to publish.

    3. 3 · The check confirms

      • ✓ construction_year is declared “not provided”, not faked
      • ✓ the local column has its own prefix and a label
      • ✓ no placeholder values such as 0 or 9999
      • 0 errors · ready to package

      A program with fixed rules: same files, same answer, every time. An AI saying “looks fine” never counts.

    AI speeds up the reading. People own the meaning. Fixed rules have the last word.

    Proposed This assisted workflow is an idea under discussion and has not been built. AI is optional: every step can be done by hand.

    05 What comes out

    One package, ready for people,
    software and AI agents.

    The result is not a database or a website. It is a folder of open files that explains itself. The same files serve someone looking at a map, a script running an analysis and an AI agent answering a question. Choose a reader to see which files it uses.

    Why the contract makes this work

    Same names, same codes

    One query, one map style or one agent prompt works for every place that follows the contract.

    Empty means unknown

    No hidden zeros or 9999s, so totals and averages are not quietly wrong.

    Every value says where it came from

    Method and coverage let a person, or an agent, say how far a number can be trusted.

    • External Portolan already defines this package layout, including README.md and AGENTS.md.
    • Documented draft The Colouring metadata inside it: meanings, methods, coverage, themes.
    • Proposed Colouring guidance for agents, and the first real package.

      07 What could people do with it?

      Comparable data
      opens new questions.

      These are possibilities, not features. They become realistic once several places deliver data under the same meaning.

      Compare cities fairly

      Building age, height or use across places — knowing the numbers measure the same thing.

      Plan energy retrofits

      Find building stock that may need attention — with modelled demand and metered consumption always kept apart.

      Read a city’s history

      Construction and demolition years, heritage designations and building condition on one map.

      Fill the gaps together

      A future contribution interface could let people add roof shapes or materials under the same definitions, marked as crowdsourced.

      Research and teaching

      Reproducible studies on open, documented data: method, source and coverage are part of the package.

      Build your own tools

      Open formats (GeoParquet, PMTiles, STAC metadata) work in many existing GIS tools, notebooks and web maps.

      Keep it yours.

      09 We need your critique

      This is a draft.
      Please push back.

      The most useful feedback is specific: a definition that doesn’t fit your data, a requirement we missed, or a reason your organisation couldn’t take part.

      1. Definitions

        Do our definitions match your reality?

        Height runs from the lowest ground point to the highest roof edge; “year built” is the completion year. Can your data say that — and what would you have to withhold?

      2. Building use

        Do eleven use classes fit your buildings?

        Residential, commercial, hospitality, public services, education, health and more — each under an INSPIRE parent. What doesn’t fit, or is drawn in the wrong place?

      3. Local needs

        What must stay local — and what should be shared?

        Which attributes from your country are essential Tier 2 detail, and which deserve to become part of the shared core?

      4. Open code lists

        How should we describe materials and roofs?

        Roof shape, facade and structural material still have no agreed code lists. Which existing classifications should we learn from?

      5. Governance

        Who should decide on changes?

        How should contract versions be reviewed and approved, and how should forks propose changes upstream?

      6. Adoption

        What would stop you from taking part?

        Licensing, effort, tooling, trust in automated mapping, hosting? Tell us what the first step would need to look like.

      Share your thoughts in the discussion today. A public channel for written feedback will be announced when this proposal is published.

      We want building data from different places to be understandable, comparable and reusable through a shared, open contract — without removing local flexibility.
